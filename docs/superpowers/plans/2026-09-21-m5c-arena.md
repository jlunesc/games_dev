# M5c Arena Features (Platforms and Cover) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A boss can have an arena with platforms (ledges to stand on) and cover (walls that block ground-level attacks); the Ashen Hound gets the first arena; the stats know when the player avoided an attack by standing on a platform or behind cover.

**Architecture:** An optional `arena` in the boss data; player physics land on floor, platform and cover tops and are blocked sideways by cover; `activeHitBoxes` cuts hit windows at the near edge of cover; the analyzer adds evasion values `platform` and `cover`; stats schema 3.

**Tech Stack:** TypeScript (strict), Vite, Vitest. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-09-21-m5c-arena-design.md` (binding; read it first). Also `docs/bosses.md`, `docs/stats.md`.

## Global Constraints
- Deterministic pure simulation, no new randomness. The flat arena (no `arena` in the boss) behaves EXACTLY as before: `tests/duelist-golden.test.ts` (4 scenarios) must pass UNCHANGED after every task; never edit its expected values.
- Recorded fights replay exactly for the Ember Duelist (unchanged); the Ashen Hound's arena changes Hound replays (documented; `GAME_VERSION` bump in Task 4).
- `parseBoss` validates the arena; `applyDials` output is re-validated (an arena must survive the dials untouched: the dials do not scale arena pieces).
- Strict CSP: no `innerHTML`, no `style=`, no `data:` URIs; drawing on the canvas only. No new dependencies. TypeScript strict, `noUncheckedIndexedAccess`, `noUnusedLocals`, `verbatimModuleSyntax`.
- Commit messages: plain, no `Co-Authored-By` or any Claude/Anthropic attribution. Never push.

### Task 2: Player physics with platforms and cover (TDD)

**Files:**
- Modify: `src/game/geometry.ts` (surfaces helper), `src/game/step.ts` (`updatePlayer`, `step`)
- Test: `tests/step-arena.test.ts` (new); golden and all existing tests stay green

**Interfaces:**
- Consumes: Task 1's `ArenaDef`; `tests/helpers.ts` (`DUELIST`, `QUIET_BOSS`, `run`, `withInput`, `advance`), `tests/boss-helpers.ts`.
- Produces: in `geometry.ts`: `interface Surface { left: number; right: number; y: number; kind: 'platform' | 'cover' }` (`y` = world y of the top surface, `WORLD.floorY - height`) and `arenaSurfaces(boss: BossDef): Surface[]` (platforms then covers, empty for a flat arena); `updatePlayer(p, input, events, arena?: ArenaDef)` gets the arena as an optional 4th parameter (absent = flat, exactly the old code path); `step` passes `boss.arena`.

Rules (in `updatePlayer`, keeping every existing line's behaviour for the flat arena):
- Horizontal: after `p.x += p.vx * DT` and the existing wall clamp, resolve covers: for each cover surface `{ left, right, y }`, if the player's feet are BELOW the cover's top (`p.y > y`, i.e. the player is lower than the top, world y grows downward) and the body overlaps the cover in x (`p.x + half > left && p.x - half < right`): if the previous x (`p.prevX`) had the body on the left side (`p.prevX + half <= left`) set `p.x = left - half`; else if on the right side (`p.prevX - half >= right`) set `p.x = right + half`; otherwise (already inside, for example standing on top or spawned inside) do nothing. A dash keeps its state (the dash simply stops moving because x is clamped; `dashTick` is unchanged).
- Vertical (replacing the floor-only landing): compute the previous feet y (`p.prevY`) and the new feet y (`p.y` after the move). The candidate landing surfaces are the floor (`WORLD.floorY`, whole width), every platform top and every cover top whose x-range overlaps the body (`p.x + half > left && p.x - half < right`). The player lands on the HIGHEST candidate surface `s` (smallest world y) with `p.vy >= 0`, `p.prevY <= s.y + 1` and `p.y >= s.y`: set `p.y = s.y`, `p.vy = 0`, `p.onGround = true`. If none is hit, `p.onGround = false`. The `+ 1` tolerance lets a player standing on a surface (prevY == s.y) stay on it. Jumping upward (`vy < 0`) never lands, so platforms are one-way.
- A player standing on a raised surface who runs off its edge: after the horizontal move no candidate surface below overlaps except the floor, so `onGround` becomes false unless the feet are at the floor, and gravity makes the player fall (next update `vy > 0`).
- Everything for `arena` undefined or with empty lists must be exactly the old behaviour (the floor is the only surface; verify with the golden test and the existing movement tests).

- [ ] **Step 1: Write the failing tests** `tests/step-arena.test.ts`: helper builds a `QUIET_BOSS` variant with an arena (`{ ...QUIET_BOSS, arena: { platforms: [...], covers: [...] } }`, skipping the validator on purpose like `QUIET_BOSS` does; use a platform `{ x: 500, width: 200, height: 130 }` and a cover `{ x: 800, width: 60, height: 120 }` unless a test needs another). Tests: (1) a player jumping straight up under the platform passes through it (vy stays negative through the platform height) and lands on top when coming down (feet y == platform y, `onGround` true, `vy` 0); (2) standing on the platform for 60 updates keeps `y` and `onGround`; running along it stays on it; running off the edge leaves `onGround` false the next update and the player falls back to the floor; (3) a jump that peaks below the platform top (a short hop, jump released early) does not land on it; (4) the cover blocks walking from the left and from the right (x stops at `left - 24` / `right + 24`), and a dash toward it stops at the same place, and does not tunnel through at full dash speed (1450 units/s = ~24 per update) even at the minimum cover width 40; (5) a player jumping over the low cover (height 120; jump peak about 155) lands on the far side; a player jumping onto the cover top stands on it (y == cover top, onGround true) and can walk off either side; (6) a player standing on the cover top is not pushed by the side rule; a player spawned inside a cover (state built by hand) is not teleported (no rule fires); (7) flat arena identical: for a scripted 600-update input, states with `arena` undefined, `{ platforms: [], covers: [] }` deep-equal each other and the golden test passes; (8) `arenaSurfaces` returns platforms then covers with `y = floorY - height`; (9) determinism: the same input gives the same states; JSON round trip of a state on a platform steps identically.

### Task 3: Cover cuts the boss's hit windows (TDD)

**Files:**
- Modify: `src/game/geometry.ts` (`activeHitBoxes`)
- Test: `tests/geometry-cover.test.ts` (new); golden and all existing tests stay green

**Interfaces:**
- Consumes: Task 1 (`arena`), Task 2 (`arenaSurfaces` is optional here; you may read `boss.arena?.covers` directly).
- Produces: `activeHitBoxes(b: BossState, boss: BossDef, options?: { ignoreCover?: boolean }): Box[]` (same as before for a flat arena or `ignoreCover: true`). Existing callers keep working (`resolveBossHits` in `step.ts`, the analyzer, the renderer): they get the cut boxes by default.

Rules: each hit window is turned into its world box as today. For every cover in `boss.arena.covers` (in the order given) with `cover.height >= hit.top` (a cover shorter than the window's top does not block it), and with the cover in front of the boss: boss facing right (`b.facing === 1`) and `coverLeft > b.x` where `coverLeft = cover.x - cover.width/2`: the box's right edge becomes `min(right, coverLeft)`; facing left and `coverRight < b.x` (`coverRight = cover.x + cover.width/2`): the box's left edge becomes `max(left, coverRight)`. A cover that contains the boss's centre (`coverLeft <= b.x <= coverRight`) or lies behind the boss does not block. If the box's width becomes 0 or negative, the box is dropped. The vertical extent never changes.

- [ ] **Step 1: Write the failing tests** `tests/geometry-cover.test.ts` (build `BossState`/boss by hand or via `createInitialState` and setting `attackId`/`attackTick`/`x`/`facing`; use the Duelist's sweep (hit window x0 0, x1 250, top 100, active from attack time 24) with an arena of one cover): facing right with a cover 150 ahead and height 120: the box is cut at the cover's near edge (width 150 minus the boss-centre distance, exact numbers); cover height 90 (below the window top 100): box unchanged; cover exactly as tall as the top (100): blocks; facing left mirrored; a cover behind the boss: unchanged; boss standing inside the cover: unchanged; a cover so close that the box has no width left: dropped (returns `[]`); two covers: the nearer one wins (cut at the nearest edge, the farther one changes nothing); a window with `bottom > 0` still cut by a tall enough cover; `ignoreCover: true` returns the uncut boxes; a flat arena and empty lists give exactly the old boxes for all four Duelist attacks at every attack time (compare to a copy of the old computation or to `boss` without `arena`); integration with `resolveBossHits`: a grounded player behind a tall enough cover is not hit by the sweep (run the real fight setup with `solo('sweep')`-style boss plus arena and a player standing behind the cover: no `playerHit`), and the same player is hit when the cover is too low.

### Task 4: Stats: evasion by platform and cover, schema 3 (TDD)

**Files:**
- Modify: `src/stats/analyze.ts`, `src/stats/record.ts`, `src/stats/export.ts` (only if it hard-codes a version)
- Test: `tests/analyze.test.ts`, `tests/record.test.ts`, `tests/export.test.ts`, `tests/loop-replay.test.ts` (extend)

**Interfaces:**
- Consumes: Tasks 1 to 3 (`arenaSurfaces`, `activeHitBoxes(b, boss, { ignoreCover })`, `playerBox`, `overlaps`).
- Produces: `Evasion = 'dash' | 'jump' | 'platform' | 'cover' | 'distance'`; `Analysis.behavior.updatesOnPlatform: number`; `STATS_SCHEMA_VERSION = 3`; `GAME_VERSION = '0.4.0'` in `src/stats/record.ts` (the comment says why).

Analyzer rules (per update while the boss is in attack mode, alongside the existing dash and jump flags, which stay exactly as they are):
- Let `cut = activeHitBoxes(after.boss, boss)` and `raw = activeHitBoxes(after.boss, boss, { ignoreCover: true })`; `real = playerBox(after.player)`.
- `coveredInDanger`: `raw.some(overlaps with real)` and NOT `cut.some(overlaps with real)`.
- `platformInDanger`: the player is standing on a raised surface (`after.player.onGround && after.player.y < WORLD.floorY - 1`) and a copy of the player box placed on the floor at the same x (`{ ...after.player, y: WORLD.floorY }`) overlaps some `cut` box, while `real` overlaps none.
- At close: `evasion` for a dodged attack is chosen by priority `dash`, `jump`, `platform`, `cover`, else `distance` (a dodged attack by a player who was also behind cover but jumped counts as `jump`, etc.).
- `behavior.updatesOnPlatform`: count of updates (whole session, including the study) with `after.player.onGround && after.player.y < WORLD.floorY - 1`.
- Everything else unchanged. The Duelist analyses stay identical apart from the new zero field.
