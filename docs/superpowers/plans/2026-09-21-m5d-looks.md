# M5d Looks Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A layered moody background, impact effects and particles, and better boss and player figures, all inside the geometric style, with an Effects switch in Settings.

**Architecture:** New pure modules under `src/ui/look/` (tuning numbers, moods, a particle system, background layout, figure primitives) with thin canvas drawing next to them; `render.ts` and `app.ts` only wire them in. The looks read the game state and events and never change them.

**Tech Stack:** TypeScript (strict), Vite, Vitest, Canvas 2D. No new dependencies, no images.

**Spec:** `docs/superpowers/specs/2026-09-21-m5d-looks-design.md` (binding; read it first).

## Global Constraints
- The looks never change how a fight plays: no edits to `src/game/`, `src/stats/`, recording or replay; `tests/duelist-golden.test.ts` unchanged and passing after every task. Drawn shapes are cosmetic; hit boxes unchanged.
- Look randomness comes only from the effects state's own tiny generator, never from the simulation's `rng`.
- Performance: at most 160 particles and 12 rings alive; static background layers pre-rendered into off-screen canvases and reused; per-frame drawing with rectangles, circles and a few polygons.
- Strict CSP: no `innerHTML`, no `style=`, no `data:` URIs (creating a canvas element with `document.createElement('canvas')` is fine); no new dependencies; TypeScript strict, `noUncheckedIndexedAccess`, `noUnusedLocals`, `verbatimModuleSyntax`.
- All colours, sizes, counts and strengths live in `src/ui/look/tuning.ts` so the owner's tweak rounds are one-file changes.
- Commit messages: plain, no `Co-Authored-By` or any Claude/Anthropic attribution. Never push. `git add` explicit paths only (other tasks run in parallel on this branch).

### Task 2: The effects system (TDD)

**Files:**
- Create: `src/ui/look/effects.ts`
- Test: `tests/look-effects.test.ts` (new)

**Interfaces:**
- Consumes: `LOOK` (Task 1), `GameState`/`GameEvent` (`src/game/state.ts`), `BossDef`, `attackBox`/`bossBox` etc. from `src/game/geometry.ts`, `WORLD`, `PLAYER`.
- Produces (all pure, immutable): `type ParticleKind = 'spark' | 'dust' | 'trail' | 'burst'`; `interface Particle { kind: ParticleKind; x: number; y: number; vx: number; vy: number; life: number; maxLife: number; size: number; color: string }`; `interface Ring { x: number; y: number; radius: number; growth: number; life: number; maxLife: number; color: string; width: number }`; `interface EffectsState { particles: Particle[]; rings: Ring[]; rng: number }`; `NO_EFFECTS` (empty, `rng` 1); `spawnEffects(fx: EffectsState, before: GameState, after: GameState, boss: BossDef, enabled: boolean): EffectsState`; `stepEffects(fx: EffectsState): EffectsState` (one real 60th of a second: move, gravity for sparks/dust, age, drop the dead, keep the caps).
- Spawn rules from `after.events` and the two states (world coordinates; y grows downward): `bossHit`: `LOOK.sparksOnBossHit` sparks at the centre of the player's swing box (`attackBox(after.player)`), a short ring; `counter`: a `counterRing` at the boss's centre plus sparks; `playerHit`: `sparksOnPlayerHit` red sparks at the player's centre, a small ring; `dash`: `trailOnDash` trail particles along the dash path start and a dust puff at the feet; player landing (`!before.player.onGround && after.player.onGround` and `before.player.vy > 300`): `dustOnLand` dust at the feet; boss landing (`before.boss.lift > 0 && after.boss.lift === 0`): dust plus a `shockwave` ring on the floor at the boss's x; `bossDefeated`: a big ring and `burstOnDefeat` burst particles at the boss's centre; `playerDefeated`: burst at the player; `phaseChange`: a white ring at the boss; `studyHit`: 4 small red sparks. Randomness only from `fx.rng` (a small LCG or mulberry32 stepped inside these functions; return the advanced value). When `enabled` is false `spawnEffects` returns `fx` unchanged (no spawn) but `stepEffects` still runs (existing effects fade).
- [ ] **Step 1: Write the failing tests** with real `step`-driven states where easy (a scripted fight producing `bossHit`, `playerHit`, `dash`, a pounce landing) and hand-made states otherwise: each event produces the expected kind and count at the expected place (sparks near the swing box centre; ring at the boss centre for a counter; dust at feet y = `after.player.y` on landing; boss landing detected from `lift` going to 0; trail for dash); the caps (spawn hundreds of events: never more than `maxParticles`/`maxRings`, the oldest are dropped); `stepEffects` ages by one, moves by velocity, applies gravity to sparks and dust (not to trails), removes life <= 0; determinism (same input gives deep-equal output), the inputs are not mutated (`structuredClone` snapshots), disabled spawns nothing, the state survives `JSON.stringify` round trip.
- [ ] **Step 2: Run to verify they fail, implement, run again.**
- [ ] **Step 3: Run everything** (as above). Only the new files and their test are added.
- [ ] **Step 4: Commit.**
```bash
git add src/ui/look/effects.ts tests/look-effects.test.ts
git commit -m "feat: add the pure impact effects system"
```
